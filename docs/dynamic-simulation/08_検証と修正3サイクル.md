# 動的計算：検証と修正の3サイクル

2026-09-05実施。実装担当5名（地形、数値計算、UI、地図表示、独立物理レビュー）と主担当の統合で実施。

## サイクル1：計算・入力・基本画面

- 開発サーバーで10項目成功、JavaScriptページエラー0。実地形62101セルをWorkerで5分間計算、高さ5→10m変更、波源ピン経路、地点数値、取消、無効・陸上座標、公式復帰、スマホ、地形503と回復を確認。
- 数値基礎・地形テストを実行し、独立レビューで水量保存・理論波速への収束試験を追加。
- 発見・修正：無効経緯度で以前の結果が残る、ピン座標の表示と内部値のずれ、パネルの二重余白。
- ビルド時にnode:fs型がブラウザ用tsconfigで解決されない問題を発見。実ファイルを読むベンチをscriptsへ移動し、ブラウザ型検査を修復。
- 証拠：`evidence/cycle-1/report.json` と同フォルダPNG。

## サイクル2：長時間・実クリック・描画障害

- 13項目成功、ページエラー0。120分・30mで陸上浸水セルと数値照会を確認。Cesium画面を実際にマウスクリックしてピン位置変更を確認。
- 描画レイヤー作成失敗を注入し、完了と誤表示せず再計算で復帰することを確認。
- 発見・修正：描画失敗が計算完了ステータスへ伝わらない。setResultをPromise化して失敗をUIへ伝播、結果を破棄。
- さらに完了直前に結果が取得できる競合を見つけ、描画準備後に結果を確定するよう修正。計算進捗を地図下部にも表示。地図下部の再試行ボタンを任意計算へ接続。
- 証拠：`evidence/cycle-2/report.json` と同フォルダPNG。

## サイクル3：本番ビルドと回帰

- `npm run build`で型検査・静的ビルド成功。
- 本番ビルドのpreviewに対し13項目成功、ページエラー0。高さ変更・実クリック・120分計算・海陸読取・取消・範囲外・陸上拒否・描画失敗・復帰・スマホ・通信失敗を再確認。
- 120分計算（136E/32N、30m、sigma100km、地域）で1588ステップ、陸上最大15.3886mを計算し、同セルの地盤からの浸水深表示を確認。これは仮想条件の数値例で実際の浸水予測ではない。

- 既存公式機能の11項目も成功（4都市、GPUバッチ、到達0分・720分停止、共有、ケース変更、スマホ、障害回復）。外部地図等の中断リクエストを別記し、ページエラーは0。

- 実地形120分ベンチ：全国・地域とも完走、全最終水深が有限・非負。保存量と波速の独立2試験も成功。

## 達成と未達を分離

達成：任意入力の都度数値計算、実地形利用、地図への海陸別着色、地点値、操作競合と障害処理、静的デプロイ可能な構成。

未達：行政・観測データに照合した現実の浸水予測精度。全国/地域で最大浸水値が大きく異なるため、数kmモデルを建物・道路単位の予測とは扱わない。摩擦・断層・堤防・高解像度地形と独立した遡上ベンチマークが今後必要。

# 再実行可能なQA計画

## 実行

1. `npm run test -- src/explorerState.test.ts` で共有URLの不正値・境界・往復を確認。
2. `npm run build` 後、別ターミナルで `npm run preview -- --host 127.0.0.1 --port 4173`。
3. インストール済みPlaywrightを指定して `QA_RUN=cycle-1 node scripts/qa-precomputed.mjs`。
4. 修正後に `QA_RUN=cycle-2`、`QA_RUN=cycle-3` を変えて再実行。各サイクルの指摘・修正・結果は親担当が記録する。

`QA_BASE_URL` は確認対象URL、`QA_EVIDENCE_DIR` は保存先、`PLAYWRIGHT_MODULE` は既存ライブラリの絶対パス、`CHROME_EXECUTABLE` は必要時のみChrome実行ファイルを指定する。既定では本リポジトリのplaywright/@playwright/test、次に既存mirror-appの依存を探す。依存追加や自動インストールは行わない。起動するのは専用のheadlessブラウザで、本人のブラウザに触れない。

## 自動検査と限界

- 1440×1000と390×844の起動、WebGL canvas寸法、アプリの起動状態を検査。スクリーンショットで実地図・地形・文字の視認性を別途人または親エージェントが確認する。canvasがあるだけでは地形読込成功と判断しない。
- 実際の同梱浸水データが読めること、到達0分、地点検査、ケース変更後の視点維持と古い地点情報の除去、共有後再読込を検査。
- 新規ページで未読込のケースのタイルに503を注入し、取得失敗表示・旧セル除去・再試行による復旧を検査。ケースが1つなら比較検査を成功扱いにせず失敗として記録。
- 外部地形・背景・建物の通信失敗は`externalFailures`、同梱データの通信失敗は`localFailures`、未処理例外は`pageErrors`に分ける。外部配信成功や建物網羅性を推測しない。
- 深さと時刻の科学的整合性、原本→集約の統計、座標変換はデータ担当の別検査が必要。E2Eは計算の正当性を証明しない。

## 証拠

`docs/precomputed/evidence/<QA_RUN>/report.json` とdesktop/mobile/network-failure PNG。`passed`は記載された検査だけの成功。未実行・取得不能・描画未確認を完了に含めない。プレビュー用データや人工セルを実データの検証証拠として使わない。

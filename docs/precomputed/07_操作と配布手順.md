# 操作と配布手順

## 1. 利用者の操作

1. 全国表示から都市ボタンを押すか、自治体名・都道府県名・自治体コードで絞り込み、自治体を選んで移動する。番地までの住所検索ではない。
2. ケース01または04を選ぶ。両ケースは「越流時に堤防が破堤」の条件。視点を固定してケースを比較できる。
3. 「最大浸水深」で集約内の最大値を色と凡例で確認する。透明度で背景の見え方を調整する。
4. 到達モードでは時刻を指定する。表示されるのはその時刻までに1cmへ到達した元セルを含む集約範囲。色の最大深さはその時刻の水深ではない。
5. 地図をクリックし、その地点周辺の集約最大深さ・最早到達時間・ケースを読む。細かい地点の実浸水深を保証する値ではない。
6. 「この視点を共有」でURLをコピーする。コピーに失敗した場合はアドレス欄または表示されたURLを使う。
7. スマホはパネルを折りたたんで地図を広く表示できる。動作が重い場合は軽量表示を選ぶ。軽量表示では建物が無効になる。

## 2. 表示の意味

- 全国3D閲覧と収録計算データの範囲を区別する。初期収録は2025年のケース01・04であり、全ケース最大でも全災害想定でもない。
- 100m・500m・2500m相当の表示セルは、10m原本を独自の緯度帯グリッドへ統計集約したもの。真の浸水境界や表示セル全域の浸水を示さない。
- 最大参考浸水深と1cm最早到達は独立した統計であり、同じ原本地点とは限らない。
- 「収録セルなし」は「浸水しない」と同義ではない。読込中・取得失敗も区別する。
- 地形・建物は外部データによる視覚的な位置関係。建物内浸水・耐震性・避難経路の安全は計算していない。
- 地形取得失敗時は平坦な地球で表示する旨が出る。再読み込みして状態を確認する。

## 3. ソース取得後の検証

Node.js 20.19以上、npm、Python 3（再変換時）を使用する。

```sh
npm ci
npm test
npm run build
npm run preview
```

ローカル確認は `http://localhost:5285`。開発は `npm run dev`、ポート5281。`build` は型チェックを含む。これらのコマンドを記載しただけではテスト成功・公開完了を意味しない。結果は検証記録で確認する。

## 4. データ再生成

[データ台帳](05_データ台帳.md) の出典・利用条件を確認し、正式配布元から対象ZIPを取得する。原本をプロジェクト外へ保存し、署名付き取得URL・認証情報を記録しない。

```sh
python3 scripts/precompute_inundation.py --input 1=/tmp/nankai-case01.zip --input 4=/tmp/nankai-case04.zip --output public/inundation
```

このコマンドはZIP CRC検査後、CSV第14列の参考浸水深と第4列の1cm到達秒から集約値を作る。負の到達秒は欠損として扱う。再実行時は指定ケースのマニフェスト項目を置換する。追加・変更後は原本SHA256、ケースと堤防条件、採用レコード数、各LODの件数を確認する。原本データが更新された場合、古い不要タイルの残存も確認して公開対象を整える。

公開するのは `public/inundation/manifest.json` と100m以上の加工集約JSON。ZIP/CSV原本、10mの全レコード、秘密情報は `public/` に置かない。詳細な変換定義と利用条件はデータ台帳を正とする。

## 5. Vercelの設定

- 想定対象: 既存 `nankai-tsunami-cesium-plateau-japan` プロジェクト。新規プロジェクトを重複作成しない。
- Framework: Vite。
- Install: `npm ci`。
- Build: `npm run build`。
- Output: `dist`。
- Node.js: プロジェクトの対応LTSを選び、ローカルの検証環境と揃える。
- 環境変数・Cesium ionトークン: 不要。
- 外部取得: 国土地理院の背景地図、PLATEAU地形・対応建物等。配信停止や通信障害の影響を受ける。

`vercel.json` にリライトルールを設けていないため、存在しないJSON等をHTMLで成功応答させない。`docs/`、`scripts/`、原本、`.env` はWeb配信対象ではない。ただしGit公開とVercelへのソースアップロードはWeb配信とは別であり、プロジェクト内に秘密ファイルを置かない。

ハッシュ付き `/assets/` は1年間のimmutableキャッシュ。未バージョン化の `/inundation/`・`/data/`・`/cesium/` は毎回再検証する。マニフェストとタイルを同じビルドで更新し、更新前から開いている利用者は再読み込みする。大量データ配布の料金・容量は実サイズと利用量に応じて確認する。

## 6. 公開前後の確認

公開前に `dist/` を棚卸しし、データが揃っていること、ZIP/CSV原本、秘密情報、開発資料が混入していないことを確認する。Viteは `public/` をそのままコピーするため、出力ディレクトリ設定だけで原本混入を防げるわけではない。

公開後はデプロイがReadyであることに加え、ルート画面、マニフェスト、実タイル、Cesium Workersが取得できることを確認する。ケース切替、都市移動、地点選択、共有URL復元、スマホ表示を実操作する。`/docs/precomputed/01_ニーズと要件整理.md` や存在しないタイルが200のHTMLにならないことも確認する。

本手順書は配布方法の説明であり、現時点の本番公開成功を保証する記録ではない。
